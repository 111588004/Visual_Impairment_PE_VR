Environmental Variable Control (環境變數控制技術文件)

文件摘要： 本文說明三大無障礙測試場景 (Stairway, Corridor, Signage) 中的環境參數控制機制。系統允許在 Runtime 即時調整照明 (Lux)、物件反射率 (LRV) 與幾何尺寸，以驗證不同環境條件下低視力患者的視覺效能。

📏 Scale Calibration Logic (尺寸縮放校正)

核心邏輯： 3D 模型原始尺寸 (Prefab) 是以「標準字高 50mm」製作的 (即 Scale = 1.0 時，字高為 5cm)。Unity 的縮放參數 (Local Scale) 依據使用者輸入的目標高度進行線性換算：

Formula:
$$ \text{Unity Scale} = \frac{\text{Target Height (mm)}}{\text{Reference Height (50mm)}} $$

Unity Parameter Mapping (參數區間實例):

  • Minimum (5mm): $$ \frac{5}{50} = 0.1 $$ (Scale)
  • Default (50mm): $$ \frac{50}{50} = 1.0 $$ (Scale)
  • Maximum (300mm): $$ \frac{300}{50} = 6.0 $$ (Scale)

4. Technical Implementation Details (技術實作原理與參數轉換)

🔥 重點總結 (Key Takeaway)

在 Unity 中設定正確 LRV 的核心步驟：

  1. 環境設定 (Environment)： 專案 Color Space 必須設為 Linear。
  2. 參數設定 (Parameter)： 將材質 Base Color (RGB) 的三個數值直接設為 LRV / 100。

舉例：若油漆廠商標示 LRV = 72，你在 Unity 的材質顏色（Base Color）只需輸入 (0.72, 0.72, 0.72)，即可得到符合物理真實感的反射效果。

本節說明物理參數如何轉換為 Unity 的渲染參數。所有轉換邏輯皆實作於場景對應的 Controller 腳本中。

4.1 LRV & Computer Graphics Theory (LRV 與電腦圖學解釋)

從電腦圖學 (Computer Graphics) 與輻射度學 (Radiometry) 的角度，本專案的 LRV 實作對應於 Physically Based Rendering (PBR) 中的 Diffuse Albedo (漫反射反照率)。

📐 理論基礎 (Theoretical Basis):

  • Physical Definition: LRV (Light Reflectance Value) 在物理上對應於 CIE XYZ 色彩空間中的 Y (Luminance Factor)。它代表表面反射的光通量與入射光通量的比率 (Ratio of Reflected Luminous Flux to Incident Flux)。
  • Linear Space: Unity 的物理渲染管線 (HDR/Linear Workflow) 模擬光的物理疊加。在這個線性空間中，材質的 Base Color 代表物體反射光線的能量百分比。
  • Mapping: 由於 LRV 與 Unity Albedo 皆屬於線性物理量 (Linear Physical Quantity)，因此無需經過 Gamma 校正 (如 sRGB 的 2.2 次方)，直接作為線性係數輸入 Rendering Equation。
渲染方程式 (The Rendering Equation Simplified):
$$ L_o = \int ( \frac{\text{LRV}}{100} ) \times L_i \times (\omega \cdot n) \, d\omega $$

其中 $\frac{\text{LRV}}{100}$ 即為材質的漫反射係數 ($k_d$ or diffuse albedo)。當 LRV=50 時，代表物體表面在物理上確實反射了 50% 的入射光能量。

4.1.2 Simplified Summary for Unity (Unity 參數設定精簡總結)

若要將上述物理定義與色彩科學精簡為 Unity 操作中的具體參數，可以整理為以下三個核心重點：

1. 核心參數對應表 (Core Mapping)

在 Unity 的 Standard Shader 或 Lit Shader (URP/HDRP) 中，物理概念與參數的對應關係如下：

物理概念 (Physical Concept) Unity 參數項目 (Parameter) 設定數值 / 格式 (Value/Format)
LRV (0-100) Base Color (Albedo) 數值： $$ LRV \div 100 $$ (例如 LRV 50 → 0.5)
CIE Y (線性亮度) RGB 頻道模式 R, G, B 三者設定為相同數值 (灰階)
Luminous Flux Ratio Alpha (A) 設定： 1.0 (不透明)
Disable Specular (移除鏡面反射) Metallic Map 設定： 0 (不可調整)
Disable Gloss (移除光澤) Smoothness 設定： 0 (不可調整)

⚠️ 為什麼不可調整 Metallic 與 Smoothness？
LRV 僅定義物體的「漫反射」(Diffuse Reflection) 特性。若開啟 Metallic 或 Smoothness，物體表面會產生「鏡面反射」(Specular Highlight) 或「光澤」(Gloss)，導致觀測到的亮度受觀察角度影響，破壞純粹基於 LRV 的輝度對比計算 (Weber/Michelson Contrast)。因此，必須將兩者設為 0 以確保物理模擬的單純性。

2. 專案環境設定 (Project Settings)

為了確保上述「直接除以 100」的邏輯成立，Unity 專案必須處於正確的色彩計算模式：

  • 參數位置： Edit > Project Settings > Player > Other Settings
  • Color Space： 必須設定為 Linear (而非 Gamma)。
  • 為什麼？ 只有在 Linear 模式下，Unity 才會將 0.5 的數值視為 50% 的物理反射能量。如果在 Gamma 模式，0.5 會因為經過曲線校正而導致亮度偏差。

3. Shader 中的具體輸入

如果你是在撰寫 Shader Graph 或 C# Script，參數精簡後的邏輯即為：

  • Shader Property： 使用 Color 屬性，並在 Color Picker 中選擇 HDR 或確保輸出為 Linear。
  • 計算公式：
    $$ \text{Unity Albedo (Linear RGB)} = \frac{\text{LRV}}{100} $$
  • 結果： 將得到的浮點數直接填入 _BaseColor 或 _MainTex_Tint。

🚀 簡化總結 (Quick Guide)

在 Unity 中模擬 LRV 的「標準動作」只需兩步：

  1. 環境： 確保 Color Space = Linear。
  2. 材質： 將 Base Color (RGB) 的三個數值都設為 LRV / 100。

舉例：若油漆廠商標示 LRV = 72，你在 Unity 的材質顏色（Base Color）只需輸入 (0.72, 0.72, 0.72)，即可得到符合物理真實感的反射效果。

代碼驗證 (Theory Verification):

// 1. LRV is CIE Y (0-100), a linear measure of reflectance.
float linearAlbedo = lrv / 100f; 

// 2. Assign directly to Linear RGB channels.
// We do NOT use Mathf.Pow(val, 2.2f) because LRV is not perceptual Lightness (L*).
Color albedoColor = new Color(linearAlbedo, linearAlbedo, linearAlbedo, 1f);

4.1.1 Actual Code Implementation (專案實作邏輯)

為了在 Runtime 高效更新大量材質而不造成 Memory Leak (如建立過多材質實例)，本專案使用 MaterialPropertyBlock 技術。以下是 ContrastController.cs 中的完整實作： 

private MaterialPropertyBlock propBlock;
// Shader Property IDs (Cached for performance)
private static readonly int BaseColorId = Shader.PropertyToID("_BaseColor");

private void SetMaterialColor(List<Renderer> renderers, float lrv)
{
    if (renderers == null) return;
    
    // Lazy Initialization
    if (propBlock == null) propBlock = new MaterialPropertyBlock();

    // 1. Calculate Linear Color from LRV
    float linearVal = Mathf.Clamp01(lrv / 100f);
    Color color = new Color(linearVal, linearVal, linearVal, 1f);

    foreach (var r in renderers)
    {
        if (r == null) continue;
        
        // 2. Get existing block to preserve other properties
        r.GetPropertyBlock(propBlock);
        
        // 3. Update only the Color property
        propBlock.SetColor(BaseColorId, color);
        
        // 4. Apply back to Renderer
        r.SetPropertyBlock(propBlock);
    }
}

4.2 Lux to Light Intensity (照度與光強轉換)

Unity 的 Light.intensity 單位並非直接等於 Lux，且深受光源類型 (Point vs Spot) 與距離衰減 (Inverse Square Law) 影響。因此，我們引入一個 **校正係數 (Intensity Factor)**，將物理照度目標值 (Em) 線性轉換為 Unity 光強度。

轉換公式 (Formula):
$$ \text{Unity Intensity} = \text{Em (Lux)} \times \text{Factor}_{\text{scene}} $$

場景係數設定 (Scene-Specific Calibration):

  • Scene 1 (Stairway): 使用多盞 Point Light 模擬均勻照明。
    Factor = 0.1 (Script: ContrastController.cs)
  • Scene 2 (Corridor): 使用 Spot Light 聚焦照明。
    Factor = 0.005 (Script: ContrastControllerS2.cs)

代碼實作 (Code Implementation):

// 範例來源: ContrastControllerS2.cs
private void UpdateLighting()
{
    // emLux 為使用者調整的目標照度 (如 300 Lux)
    // intensityFactor 為場景特定的校正參數 (如 0.005)
    float finalIntensity = emLux * intensityFactor;

    foreach (var light in targetLights)
    {
        light.intensity = finalIntensity;
    }
}

🔢 計算範例 (Calculation Example)

假設使用 Point Light 且校正係數為 0.03 (Factor = 0.03)：

  • 情境： 將環境照度 (Lux) 從 0 lx 調整至 1000 lx。
  • 計算：
    • Min: $$ 0 \times 0.03 = 0 $$
    • Max: $$ 1000 \times 0.03 = 30 $$
  • 結果： Unity Inspector 中的 Light Intensity 數值範圍將會是 0 ~ 30。

💡 Why Factors Differ? (為何係數不同?)

係數差異來自於光源的物理特性模擬：Scene 1 的 Point Light 向全方位發散，能量衰減快，因此需要較高的係數 (0.1) 才能在地面維持目標照度；Scene 2 的 Spot Light 光束集中，能量利用率高，因此係數較低 (0.005)。這些數值是透過數位光度計校正後得出的經驗值。
