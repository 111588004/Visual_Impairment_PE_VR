Cataract Simulation System
白內障模擬系統技術架構書

文件摘要： 本文檔說明了白內障 (Cataract) 模擬系統的四大核心病理特徵（視力模糊、對比敏感度下降、黃化、散射眩光）及其在電腦圖學 (CG) 中的實作對應關係。

1. Visual Simulation Model (視覺模擬模型)

本系統基於臨床白內障症狀，透過 Shader 後處理技術 (Post-processing) 重現水晶體混濁後的視覺體驗。以下為四大核心病理特徵的技術實作：

2. Mathematical Model (數學模型與演算法)

在 HLSL Shader (CataractSimulation.shader) 中，我們依序執行以下像素處理步驟：

Step 1: Visual Acuity Loss (視力模糊)

模擬視網膜無法精確聚焦的高頻細節喪失。

1. Implementation (圖學實作):

使用 URP Depth of Field (Gaussian) 模式，將 Focus 距離設為 0 以涵蓋全域，透過控制 Gaussian Max Radius 來決定模糊強度。

2. Unity Parameter:
_dof.gaussianMaxRadius
  • Sim. Default: 2.5 (Matches Moderate_20_100)
  • Adjustable Range: 0.0 ~ 5.0
3. Clinical Target:
Snellen 20/100 (Moderate)
當 Radius 為 2.5 時對應中等程度低視力，最高可調至 5.0 (20/200)。

Step 2: Contrast Sensitivity Loss (對比敏感度降低)

模擬因介質混濁導致的成像霧化與動態範圍壓縮。

1. Math Definition (數學定義):
$$ C_{out} = (C_{in} - 0.5) \cdot Factor + 0.5 $$

以 0.5 (中性灰) 為中心進行對比度縮放，\(Factor < 1.0\) 表示對比降低。

2. Unity Parameter:
_Contrast (Multiplier)
  • Sim. Default: 0.4 (Matches LogMAR 0.6)
  • Adjustable Range: 0.0 ~ 1.5
3. Clinical Target:
LogMAR 0.6
對應到 Factor 約 0.4 ~ 0.5。

Step 3: Intraocular Scattering & Glare (眼內散射與眩光)

模擬光線在混濁晶狀體內的漫射所造成的失能性眩光 (Disability Glare) 與光幕效應。

1. Implementation (圖學實作):

透過 URP Volume 或自訂 Bloom 後處理，將亮度超過門檻值的像素提取出來，利用大範圍的高斯模糊或雙線性濾波進行降採樣及升採樣擴散，最後將其相加 (Additive Blending) 回原影像中。

2. Unity Parameter:
glareIntensity (Bloom Intensity)
  • Sim. Default: 1.0
  • Adjustable Range: 0.0 ~ 5.0
  • Threshold: 0.5 (中亮度以上即散射)
3. Clinical Target:
Disability Glare
模擬病人在強光或夜間燈光下的刺眼感與對比度急劇下降。

Step 4: Yellowing (水晶體黃化)

模擬核性白內障 (Nuclear Sclerosis) 對短波長光線的吸收。

1. Math Definition (數學定義):
$$ C_{final} = C_{in} \cdot Tint_{color} $$

RGB 通道的乘法濾鏡 (Multiply Filter)。

2. Unity Parameter:
_Tint (RGBA)
  • Sim. Default: RGB(1, 0.95, 0.85)
  • Adjustable Range: Color Picker (All RGB)
3. Clinical Target:
Nuclear Color
典型值 RGB(1.0, 0.95, 0.85)。

3. System Architecture (系統架構)

  • Controller (CataractRenderer.cs)
    負責將臨床參數 (Enum: Snellen 20/20~20/200, Float: Contrast) 轉換為 Shader 所需的浮點數值。
  • Shader (CataractSimulation.shader)
    以 Opaque 或 Overlay Queue 執行全螢幕後處理，確保效能並正確覆蓋於 3D 場景之上。
  • Alternative (CataractVolumeControl.cs)
    (實驗性) 使用 Unity URP 原生 Volume Stack (DepthOfField + ColorAdjustments) 來達成類似效果，優點是與引擎整合度高，但對特定病理特徵 (如特定的黃化曲線或散射模式) 控制力較 Shader 弱。
